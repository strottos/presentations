# How did we get here?

Keep it moving, roughly 30-45 seconds per slide. Each era solved a real problem and
created the next one.

- Punch cards: not strictly before teletypes (cards were the main input until the
  mid-1970s, and lingered to the mid-80s), but batch is the step _before_ interactive.
  Cards go back to Jacquard's loom (early 1800s) and Hollerith's 1890 census machines;
  IBM's 80-column card is from 1928. Write, punch, hand to the operator behind the
  counter, queue, wait. Columns 73-80 held sequence numbers so a dropped deck could go
  through a card sorter; the stripe in the photo is the low-tech backup. Fun facts:
  early Fortran only used 72 columns because the IBM 704's reader could only read 72
  in one pass; a card with every hole punched was a "lace card" and jammed the reader.
  The 80 columns shaped terminal widths (IBM 3270, VT100), set up the VT100 slide.
  (Wikipedia: Punched card; Computer programming in the punched card era.)
- Teletype: the big step is _interactive_. Type a line, get an answer straight away.
  The ASR-33 was the classic Unix console. `/dev/tty` and the `\r\n` thing
  in raw mode (Part 4) both come straight from this machine. Callback later.
- VT100: not the first video terminal, but the most emulated one (vt100.net calls it
  "probably the most famous terminal name in the world"). It used ANSI X3.64 codes but
  had no colour, no italics and couldn't hide its cursor: those came later (VT220,
  ECMA-48, xterm). xterm will still answer a device query as "VT100 with Advanced Video
  Option". Its 132-column mode only had 14 lines.
  `vi` predates it (Bill Joy, mid 1970s, on an ADM-3A, which is also why `hjkl` are
  arrow keys and `~` is home). "Your terminal is still pretending to be a VT100" sets up Part 3.
- curses/Rogue: termcap came out of Bill Joy's vi work. curses was Ken Arnold, ~1978,
  and Rogue (Toy & Wichman, ~1980) was its most famous early user. Arnold literally
  lifted vi's cursor-movement code for it. Fun facts: Arnold got involved because Rogue's
  screen updates through his own library were painfully slow over a modem. `@` was chosen
  because it shows you where you're "at". Dennis Ritchie called Rogue "the biggest waste
  of CPU cycles in history". Point out "draw to a
  buffer, send minimal updates" is _exactly_ what Ratatui does in Part 4. 45 years later.
- Macintosh: be fair here, GUIs were a huge win for normal people. Xerox PARC pioneered
  it (Alto, 1973), building on Engelbart's NLS at SRI, which is where the mouse actually
  came from. Lisa came first (1983), the Mac (24 Jan 1984) made it mainstream.
- 1990s: the pain was every platform having its own toolkit. Java's answer was
  "write once, run anywhere". Land the "look weird everywhere" line.
- 2000s: the web won because of distribution: no installs, instant updates. Web 2.0 map
  gets a laugh from anyone old enough to remember "folksonomy".
- Electron: genuinely a win for shipping cross platform. The image is the joke. Then
  the punchline slide: 400MB of node_modules to render a list. Land it, move on.
- Not anti-GUI or anti-web, just "right tool for the job" and the terminal is
  underrated.

# The mad stuff

- Doom: demo doom-cli (github.com/ludocode/doom-cli). Draws Doom's 320x200 frame with
  Unicode sextant blocks (6 pixels per cell, two colours per cell: bright pixels become
  the foreground, dark ones the background). Terminals never send key-up events, so it
  guesses releases from your key repeat timing, and you can only hold one key at a time.
  Controls: arrows move, `z` shoots, space opens doors. Sound section of its README:
  "Nope." terminal-doom (kitty graphics) is the real-pixels comparison if in kitty/Ghostty.
- Carbonyl: open Wikipedia's "Text-based user interface" page: a TUI rendering a web page
  about TUIs. If time, show YouTube too, it's genuinely ridiculous.
- MapSCII: zoom into wherever the talk is happening.
- terminal.shop: show the menu, maybe don't actually buy coffee live.
- Rapid fire the silly ones: `sl`, `cmatrix`, `cbonsai -l`, `asciiquarium`, `ls | lolcat`.

# How it works

- The `+exec` snippet runs live: press `ctrl+e` on that slide to run it.
- Alt screen: show `less` on a file, quit, scrollback is untouched.
- Raw mode: run `cat -v` and press arrow keys to show the escape bytes. Ctrl-D to exit.
- `stty -a` shows the cooked-mode settings if anyone asks.
- Fun fact if time: Ctrl-S "freezing" your terminal is XON/XOFF flow control, left over
  from pausing output for slow printers. Ctrl-Q unfreezes. (Linus Åkesson, The TTY
  demystified)
- If a demo leaves the terminal broken: `reset` or `stty sane`.

# Q&A ideas

- "Accessibility?" Honest answer: TUIs are worse for screen readers than good GUIs/web.
  Text is there but layout semantics aren't.
- "Windows?" Windows Terminal is great now, crossterm/Bubble Tea/Textual all support it.
